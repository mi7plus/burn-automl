# v1.0 Definition of Done

Each item of the PRD §28 definition of done, mapped to where it is satisfied in
the codebase. The end-to-end integration suite
(`crates/automl-tasks/tests/end_to_end.rs`) exercises the cross-cutting strands
against the real public API.

| DoD item (§28) | Where it lives | Proof |
|----------------|----------------|-------|
| Optimize arbitrary Rust objectives, single- or multi-objective | `automl-core::study`, `objective`, `pareto` | `end_to_end::hpo_persists_and_resumes`, `multi_objective_builds_a_pareto_front` |
| Sequential, process-parallel and distributed execution per §18.2 | `executor` (`SequentialExecutor`, `ThreadExecutor`), `distributed` (`Worker`, lease protocol) | `end_to_end::distributed_workers_drain_exactly_once`; `distributed` failure-injection suite |
| Persistent studies survive failures and resume without data loss | `storage`, `sqlite` (versioned migrations), `Study::resume` | `end_to_end::hpo_persists_and_resumes`; `distributed` orphan-recovery tests |
| Production Random, Grid, TPE (conditional-hardened §5.1), an evolutionary method, multi-objective via `ParetoFront` | `sampler`, `tpe`, `evolution`, `qmc`, `pareto` | per-module tests; `benchmarks` example |
| Median/percentile pruning + ASHA/Hyperband, with a robust-aggregation mode for noisy objectives | `pruner` (`MedianPruner` incl. `with_robust_window`, `AshaPruner`), `robust` | `pruner`, `robust` tests |
| Burn integration: metrics, pruning, checkpoints, device-aware execution | `automl-burn`, `scheduler` (`DeviceScheduler`), `checkpoint` | `automl-burn` module tests |
| Examples across supervised, time series, Transformers, vision, unsupervised, audio, video, RL, generative, multimodal | `automl-burn` (`AutoVision`/`AutoSegmentation`/`AutoDetection`/`AutoAudio`/`AutoVideo`/`AutoTransformer`/`AutoAutoencoder`), `automl-tasks` (`AutoCluster`/`AutoAnomaly`/`AutoRl`), `fusion` | each module's tests |
| NAS searches architecture graphs or reusable blocks | `automl-core::nas` (`MacroSpace`), `automl-burn::nas` (`AutoNas`) | `end_to_end::nas_architecture_search_via_ordinary_optimization` |
| Pipeline AutoML searches preprocessing → model → postprocessing conditionally | `automl-core::pipeline` (`PipelineSpace`), `automl-tasks::pipeline` (`AutoPipeline`) | `end_to_end::pipeline_search_end_to_end` |
| Multimodal: searchable encoders, fusion, constraints validated before scheduling | `automl-core::fusion` (`MultimodalSpace`, `MultimodalPlan::validate`) | `end_to_end::multimodal_validates_before_scheduling` |
| Winning trials reproducible from stored configuration and provenance | `provenance` (`EnvSnapshot`, `TrialTiming`), deterministic sampling | `end_to_end::replay_is_deterministic` |
| Inspect history, importance, learning curves, resources, Pareto fronts | `importance`, `automl-cli` dashboard (learning-curve overlays, utilization) | `importance`, `automl-cli` tests |
| Custom objectives first-class; high-level APIs optional | `Objective` / `ReportSink` seam; `Auto*` are thin builders over `Study` | throughout |
| Public API under strict semver with a documented migration guide | [STABILITY.md](STABILITY.md), [MIGRATION.md](MIGRATION.md); v1.0.0 tag | this release |
